1. توضیح تکلیف، نمره‌دهی و توسعه‌ها

توضیح

برای بستهٔ کاری ۳ از FeathersJS (فریم‌ورک بالای Express/Koa با سرویس‌ها و hookها و پشتیبانی Socket.io) استفاده می‌کنید. یک سناریوی شخصی انتخاب می‌کنید که نباید از یک tutorial کپی شده باشد. حداقل ۳ فیلد باید اعتبارسنجی ورودی (validation) داشته باشند و حداقل ۴ route با authentication بسازید و در http-client (وب‌استورم) یا Postman نشان بدهید. با این کار ۱۲ از ۲۰ می‌گیرید.

// مثال: اعتبارسنجی ۳ فیلد با اسکیمای TypeBox (Feathers v5)
export const bookSchema = Type.Object({
  title:  Type.String({ minLength: 2 }),
  author: Type.String({ minLength: 2 }),
  year:   Type.Integer({ minimum: 1400, maximum: 2100 })
});

// احراز هویت روی سرویس
app.service('books').hooks({
  before: { all: [authenticate('jwt')] }
});
خروجی
POST /books  بدون توکن           -> 401 Unauthorized
POST /books  با year="abc"       -> 400 BadRequest (validation)
POST /books  با توکن و دادهٔ درست -> 201 Created
⚠️ «۴ route با authentication» یعنی چهار endpoint (مثلاً GET/POST/PATCH/DELETE روی یک سرویس) که بدون توکن معتبر جواب ندهند و در demo نشان داده شوند.

توسعه‌ها (نمرهٔ اضافه)

+۲ فرانت‌اند برای این تکلیف. +۲ نوشتن تست با حداقل ۶۰٪ code coverage (راهنمای تست در سایت Feathers). +۲ نشان دادن استفادهٔ socketها (Socket.io) در فرانت‌اند: مثلاً با رویدادهای created، updated، removed UI بدون refresh به‌روز می‌شود. +۲ role-based authentication با featherspermissions (نقش‌هایی مثل admin و user با دسترسی متفاوت).

// فرانت‌اند: گوش دادن به رویداد بلادرنگ
client.service('books').on('created', book => addToList(book));

نکات ارزیابی

هر ۱۵ دقیقه push کنید (بدون commit history نمره‌ای نیست)؛ به سؤال‌های کد در progress report و دفاع جواب بدهید؛ در دفاع تکه‌ای از کد حذف می‌شود و باید بازسازی کنید (بدون Ctrl-Z یا git reset --hard HEAD)؛ کپی از ChatGPT/Grok ممنوع، جست‌وجو مجاز.

⛔ سناریوی کپی‌شده از tutorial نمرهٔ صفر یا کسر نمره دارد؛ موضوع خودتان را انتخاب کنید (مثلاً کتابخانه، باشگاه، رزرو).
